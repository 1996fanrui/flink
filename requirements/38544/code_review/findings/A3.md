# A3. Filter 写 spillFile 用 NEW channelInfo

## 设计期望

filter 阶段调用 `accumulator.beginChannel(...)` 时必须使用 NEW（post-rescale，`mappedChannel.getChannelInfo()`）的 channelInfo，因为这是 drain 阶段查物理 channel 的 key（`SpillFileReader.channelByInfo` 由 `physicalChannels` 的 `getChannelInfo()` 派生）。
filter 内部寻址虚拟通道继续用 OLD（`channelInfo.getInputChannelIdx()`），因为 virtual channel registry 是按 `(oldSubtask, oldChannel)` 键的。
非 rescale 路径 OLD == NEW 时该错误不可见，rescale upscale/downscale/rebalance 路径才暴露。其它任何把 `channelInfo` 当 spillFile / 物理 channel lookup key 的位置都必须用 NEW 方向。

## 符合预期

- `RecoveredChannelStateHandler.java:247` `accumulator.beginChannel(channel.getChannelInfo())` 使用的是 `getMappedChannels(channelInfo)` 返回的 `RecoveredInputChannel`，且 `calculateMapping`（`:389-399`）通过 `oldToNewMapping.getMappedIndexes(info.getInputChannelIdx())` 得到 NEW 索引、`getChannel(gateIdx, NEW_index)` 取物理 channel，物理 channel 的 `channelInfo` 在 `InputChannel.java:107` 构造为 `new InputChannelInfo(gateIndex, channelIndex)`，因此 `beginChannel` 入参确认是 NEW。
- `RecoveredChannelStateHandler.java:251-253` `filterAndRewrite(channelInfo.getGateIdx(), oldSubtaskIndex, channelInfo.getInputChannelIdx(), ...)` 中 `channelInfo` 是 `recover` 的入参（OLD），第三个参数 `oldChannelIndex` 也明确是 OLD —— 与 `ChannelStateFilteringHandler.filterAndRewrite` 签名（`:115-120` 参数名 `oldChannelIndex`）一致；filter 内部寻址仍是 OLD。
- `RecoveredChannelStateHandler.java:240-246` 的注释明确解释了两方向选择，与设计 §3a 一致：spillFile 写盘用 NEW，filter 内部继续用 OLD。
- `FilteredBufferWriter.flush()` 在 `spillFile.append(currentChannel, payload)`（`:116`）使用 `currentChannel`，该字段在 `beginChannel`（`:82`）被设置为 NEW，且 `requestBufferBlocking` 触发的 flush 走 `InputChannelInfo saved = currentChannel; flush(); currentChannel = saved;`（`:98-100`），保证 buffer-full flush 也用 NEW 写盘。
- `SpillFile.append` 把 `channelInfo` 直接落进 `Entry`（`:230`），后续 drain 与 Step 3 链路无任何重新解释，方向贯穿到底。
- 全文件 grep `beginChannel`（生产代码），唯一 caller 即 `:247`；不存在第二处可能误用 OLD 的旁路。
- `SpillFileReaderBootstrap.collectRecoveredChannels`（`:48-61`）用 `ch.getChannelInfo()` 建源 channel map，`buildReader`（`:88-96`）也用同一物理 channel 集合派生 `channelByInfo`。drain 用 `channelByInfo.get(e.channelInfo)`（`SpillFileReader.java:107`）与 `bufferRequester.requestBufferBlocking(e.channelInfo)`（`:115`）两条 lookup 链使用的 key 类型与 entry 写入端完全对齐，rescale 路径下 NEW 端到端闭环。
