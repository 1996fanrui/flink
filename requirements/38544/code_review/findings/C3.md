# C3. End-of-drain finishReadRecoveredState 必调（含异常路径）

## 设计期望

- `coordination.md` §7 与 `unspiller.md` §4 step (D) 明确：drain 退出（含异常退出）必须对 `allChannels` 每个 channel 调用一次 `finishReadRecoveredState()`，否则 `allRecoveredBuffersDelivered` 不翻 true，下游基于 `inRecovery` 判定的所有路径（`getNextBuffer`、`checkpointStarted`、`stateConsumedFuture` 完成条件）将永久 hang。
- review_checklist.md C3 进一步约束：(1) drain 主循环外 try/finally，finally 内对 `allChannels` 全部调；(2) 不允许只对处理过的 channel 调；(3) 单 channel 抛错不能中断后续 channel；(4) task cancel 路径也要跑；(5) (D) 后不要再插逻辑。

- `flink-runtime/src/main/java/org/apache/flink/streaming/runtime/tasks/StreamTask.java` 942-968（drain runnable 外层调用 + 异常处理）

## 符合预期

- (D) 末段循环遍历的是 `allChannels`（`SpillFileReader.java:136`），不是"处理过的 channel 子集"——满足 checklist "不允许只对处理过的 channel 调"。
- `allChannels` 在构造时由 `SpillFileReaderBootstrap.collectPhysicalChannels(inputGates)` 收集了 task 全部物理 channel（`StreamTask.java:1078-1082`），覆盖 rescale 下未收到任何 entry 的 channel。
- (D) 之后 `drain()` 立即返回，没有再插任何逻辑（`SpillFileReader.java:138-139`）——满足 "(D) 后不要再插逻辑"。
- 接口签名 `void finishReadRecoveredState() throws IOException`（`RecoverableInputChannel.java:70`）明确允许 checked exception，调用方有义务处理。
- Remote/Local 的实现都在 channel monitor 内一次性翻转 flag（`RemoteInputChannel.java:248-252`、`LocalInputChannel.java:189-194`），happens-before 给 consumer 可见。

## 不符合预期

- `SpillFileReader.java:99-139` `drain()` 通体没有 `try/finally`：drain 主循环 (A)/(B)/(C) 任意一步抛异常（`requestBufferBlocking` 中断、`readBytesAt` IOException、`channelByInfo.get` null IllegalStateException line 108-111）会沿 throw 直接出 `drain()`，line 136-138 的 (D) 循环根本不会执行。违反 checklist "drain 主循环外 try/finally；finally 内对 allChannels 全部调"。
- `SpillFileReader.java:136-138` (D) 循环本身没有 try/catch：若 `allChannels` 第 1 个 channel 的 `finishReadRecoveredState()` 抛 IOException（接口 line 70 允许），后续 channel 永远拿不到 flag 翻转。违反 checklist "单 channel finishReadRecoveredState 抛不能中断后续 channel 调用（swallow 或 suppressed）"。
- `StreamTask.java:956-968` 外层只做了 `catch (Throwable) → handleAsyncException → finally close()`，**没有兜底补调** 任何 channel 的 `finishReadRecoveredState`。一旦 (D) 因前述任一原因未跑完，下游 `stateConsumedFuture` 永远不完成（Local/Remote 的完成条件只看 `allRecoveredBuffersDelivered && recoveredBuffers.isEmpty()`）；`spillReader.close()` 也只释放 buffer 和 spillFile grant，不触发 channel 端 flag。
- `StreamTask.java:944-947` task cancel/InterruptedException 路径：drain runnable 通过 `drainHandoff.get()` 中断时直接 `Thread.currentThread().interrupt(); return;`，连 `spillReader.drain()` 都不会进，自然没有任何 `finishReadRecoveredState` 调用。即使进入 `drain()` 后被中断，line 99 的 `throws InterruptedException` 也会绕过 line 136-138。违反 checklist "task cancel 路径也得跑"。
- `RecoveredChannelStateHandler.java:364-367` 既有的 `inputGate.finishReadRecoveredState()` 兜底只对 `instanceof RecoveredInputChannel` 生效（`SingleInputGate.java:459-461`）；filter-on 路径下 conversion 已经把 channels 转成 Local/Remote，这条兜底对 C3 关心的 channel 类型完全无效，不构成 fallback。

## 总评

FAIL — `SpillFileReader.drain()` 缺 try/finally，且 (D) 循环不 swallow 单 channel 异常，外层 StreamTask 也无补调；drain 中途抛错或 task cancel 会让 `allRecoveredBuffersDelivered` 永远停在 false，下游 `stateConsumedFuture` 永久 hang，正是 C3 所要避免的核心场景。
