# E1 — RecoverableInputChannel 接口 + 不向下 cast

## 设计期望

- drain 只通过 `RecoverableInputChannel` 接口（`onRecoveredStateBuffer` + `finishReadRecoveredState`）访问 channel，永不 cast 到具体子类。
- `SpillFileReader.channelByInfo` 的 value 类型必须是接口。
- 仅 `RecoveredChannelBufferRequester` 允许持有 `RecoveredInputChannel`（filter 期间未转换的源 channel）。
- `RecoveredInputChannel.toInputChannel()` 迁移路径走同一接口入口。
- 不允许在 drain 路径上出现 `instanceof RecoveredInputChannel/LocalInputChannel/RemoteInputChannel` 这类分支。

## 符合预期

- 接口在 `RecoverableInputChannel.java:32-71` 声明，仅暴露 `getChannelInfo` / `onRecoveredStateBuffer` / `finishReadRecoveredState` 三个方法，未泄漏 channel 具体类型。
- 三个 channel 全部实现该接口：`RecoveredInputChannel.java:52-53`、`LocalInputChannel.java:66-67`、`RemoteInputChannel.java:77`。
- `SpillFileReader.allChannels` (L52)、`channelByInfo` (L53) 和构造器入参 (L77) 全部用 `RecoverableInputChannel` 类型；drain 主循环 (L107、L136) 与 Step 1 (L164) 仅通过该接口调用，没有任何 `instanceof` / 向下 cast（grep `instanceof.*Channel` 在 SpillFileReader.java 无命中）。
- `RecoveredChannelBufferRequester.java:36-60` 是设计中允许的唯一持 `RecoveredInputChannel` 的实现（filter 期间源 channel 的 buffer 申请 + 释放），并以 `package-private` 限制在 `checkpoint.channel` 包内（L36 `final class`）。
- `RecoveredInputChannel.toInputChannel()` 在 `RecoveredInputChannel.java:130-141` 迁移走同一接口入口：先 `toInputChannelInternal()` 拿到物理 channel，再用 `RecoverableInputChannel.onRecoveredStateBuffer` + `finishReadRecoveredState` 推送剩余 buffer，与 drain 通路语义一致。
- `SpillFileReaderBootstrap.collectPhysicalChannels` (L69-81) 与 `StreamTask.java:1078-1082` 调用链返回 `List<RecoverableInputChannel>`，喂给 `SpillFileReader` 的也是接口类型。
- `UnknownInputChannel.markNoRecovery` (L216-223) 用 `RecoverableInputChannel` 类型形参调用 `finishReadRecoveredState`，未做任何向下 cast。

## 不符合预期

- 无。`SpillFileReaderBootstrap.java:55-56` 与 `RecoveredInputChannel.java:136-137` 的 `instanceof` 仅用于"收集阶段"的类型甄别（前者从 `InputGate.getChannel(i)` 这个 `InputChannel` 视野中筛出 `RecoverableInputChannel`；后者从迁移路径中的 physical `InputChannel` 视野中筛出 `RecoverableInputChannel`），都不在 drain 路径上，且向下 cast 的目标是接口本身而非任何具体子类；与设计期望"drain 永不 cast"一致。`RecoveredChannelStateHandler.java:377-381` 的 cast 在 filter 路径用于源 channel，本就允许。

## 总评

PASS — drain 与 Step 1 全程通过 `RecoverableInputChannel` 接口访问 channel，未观察到任何回退到具体子类的分支或 cast。
