# A1. Filter 期间内存 bounded

## 设计期望

Filter 期间内存只持单 prefilter buffer + 单 postfilter buffer 两个 segment 的常量，master 上把 buffer pool 用尽后改走 `MemorySegmentFactory.allocateUnpooledSegment` 的 heap fallback（per-buffer 分配，会随 recovery 量线性增长）必须被彻底删除并替换成"写盘"路径。

- `flink-runtime/src/main/java/org/apache/flink/runtime/checkpoint/channel/RecoveredChannelStateHandler.java:174-189`（`getPreFilterBuffer` — prefilter 单实例）

## 符合预期

- `RecoveredInputChannel.requestBufferBlocking` 只剩 `bufferManager.requestBufferBlocking()` 一条路（RecoveredInputChannel.java:345-353），无任何 `allocateUnpooledSegment` 兜底。
- filter 路径内 grep `MemorySegmentFactory.allocateUnpooledSegment` 仅命中 RecoveredChannelStateHandler.java:181，且只对 `preFilterSegment` 单次 lazy allocate；其他 master 调用点（`SpanningWrapper`、`SortBasedDataBuffer` 等）与 filter 路径无关。
- prefilter buffer 是 `RecoveredChannelStateHandler.preFilterSegment` 单实例，`getPreFilterBuffer`（行 174-189）在 issue 前用 `preFilterBufferInUse` 做 fail-loud 校验，recycler 仅翻 flag 不释放 segment，segment 本身只在 `close()`（行 368-372）才 `free()`，恰好对应 checklist 的"reusable 单实例"。
- postfilter buffer 是 `ensureSpillFileWriter`（行 296）从 `channel.requestBufferBlocking()` 一次性取的 exclusive pool buffer；段被剥出来包成 no-op recycler 的 `NetworkBuffer`（行 299-304）交给 `FilteredBufferWriter`，filter 期间任何 `recycleBuffer` 都不会归还到 pool。
- `FilteredBufferWriter.requestBufferBlocking`（FilteredBufferWriter.java:95-103）当 `outputBuffer` 满时先 `flush()` 写盘再返回同一个 buffer 的 `retainBuffer()` —— 验证了"buffer 满 → 写盘 → 复用同一个 segment"的 bounded 语义，不会新分配第二个 postfilter buffer。
- filter 结束（handler `close()` 行 347-373）：先 `spillFileWriter.close()` flush 残余，再 `filterOutputPooledBuffer.recycleBuffer()`（行 361）把 pooled buffer 归还到 channel 的 exclusive pool，最后 `preFilterSegment.free()`（行 369）释放 unpooled segment，两个 buffer 都正确释放，无 leak。
- `ChannelStateFilteringHandler.BufferSupplier`（行 265-267）是 filter 路径唯一申请 buffer 的入口，filter-on 路径上 `bufferSupplier` 实例只能是 `FilteredBufferWriter`（RecoveredChannelStateHandler.java:238 + 250-255），不可能反向调到 `channel::requestBufferBlocking`。
- `SequentialChannelStateReaderImpl.readInputData`（行 88）将 `memorySegmentSize` 传给 handler，`InputChannelRecoveredStateHandler` 构造（RecoveredChannelStateHandler.java:141-143）`checkArgument(memorySegmentSize > 0, ...)`，防御性校验存在。

## 不符合预期

- 无。

## 总评

**PASS** — A1 的两个核心要求（heap fallback 删除 + filter 期间 buffer 数量 bounded 为 prefilter/postfilter 各 1）在当前 working tree 中均落地，prefilter 单实例复用 + postfilter pool buffer + no-op recycler + close 时双双释放的链路完整可追踪。
