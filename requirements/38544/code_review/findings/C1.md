# C1 — SpillFileReader.lock 两条铁则（Principle 1 + 2）

## 设计期望

- Principle 1：recovery 期间所有对 `RecoverableInputChannel.recoveredBuffers` 的写（drain 的 `onRecoveredStateBuffer(buf)` 与 Step 1 的 `onRecoveredStateBuffer(barrier)`）必须在 `synchronized (SpillFileReader.lock)` 内；end-of-drain `finishReadRecoveredState()` 例外。
- Principle 2：`currentSegmentIndex / currentOffset` 的推进必须与对应的 `ch.onRecoveredStateBuffer(buf)` 在**同一**个 `synchronized (lock)` block 内。
- 锁是命名字段 `private final Object lock`（非 `synchronized(this)`），grep-able、`@GuardedBy` 注解可见；锁顺序 `SpillFileReader.lock → channel-internal queue monitor`；lock 内禁止阻塞/IO/park。

## 符合预期

- `SpillFileReader.java:62` 锁是命名 `private final Object lock = new Object();`，不是 `synchronized(this)`。
- `SpillFileReader.java:64-68` `currentSegmentIndex` / `currentOffset` 字段带 `@GuardedBy("lock")` 注解。
- `SpillFileReader.java:126-131` drain 关键 4 动作（`onRecoveredStateBuffer` + `pollNextEntry` + 两个 offset 赋值）在**同一**个 `synchronized (lock)` block 内，Principle 2 满足。
- `SpillFileReader.java:115` `bufferRequester.requestBufferBlocking` (A) 在 lock 外；`SpillFileReader.java:119-122` 磁盘读 (B) 在 lock 外；与设计 §4(A)(B) 一致，park 不在锁内、不会阻塞 Step 1。
- `SpillFileReader.java:136-138` end-of-drain `finishReadRecoveredState()` 在 lock 外（Principle 1 显式例外）。
- `SpillFileReader.java:147-169` Step 1 `snapshotAndInsertBarriers` 在 `synchronized (lock)` 内完成 `spillFile.snapshot()` + 抓 `(startSegmentIndex, startOffset)` + 给每个 channel 插入 `RecoveryCheckpointBarrier`，与 Principle 1（barrier 插入也在 lock 内）+ Principle 2（startPos 与 barrier 插入同块）一致。
- `LocalInputChannel.java:170` / `RemoteInputChannel.java:228` channel 实现使用 `synchronized(recoveredBuffers)` / `synchronized(receivedBuffers)` 作为内层锁，匹配 `SpillFileReader.lock → channel monitor` 的全局顺序，无反向。
- `SpillFileReader.java` 中 `onRecoveredStateBuffer` 仅在 drain（line 127）和 Step 1（line 165）两处被 SpillFileReader 调用，均在 lock 内；与设计 §4 "(C) 是唯一推进点 & 唯一调用 `onRecoveredStateBuffer` 的地方" 一致。
- 包外 lock 外调用 `onRecoveredStateBuffer` 的两处都属于设计豁免：`RecoveredChannelStateHandler.java:217-222` 是 filter-off 通路（无 spiller）；`RecoveredInputChannel.java:136-141` 是 `toInputChannel()` 单线程迁移（物理 channel 尚未对外暴露，无 spiller）。
- `SpillFileReader.java:108-111` drain 找不到 `channelByInfo.get(e.channelInfo)` 时 throw `IllegalStateException`，未对 Principle 1/2 路径放水（fail-loud）。

## 不符合预期

- `SpillFileReader.java:106`：`seg.peekNextEntry()` 在 lock 外读取 `SpillFileSegment.drainEntries`。该字段同时被 lock 内的 `seg.pollNextEntry()`（line 128）和 `currentSegmentIndex` 写入物理上来自同一 channelIOExecutor 线程，单写者，但 Principle 1 的文字定义是 "advancing `(currentSegmentIndex, currentOffset)` 与 `onRecoveredStateBuffer` 同一 sync block"；peek 不修改 cursor，在 lock 外读 `drainEntries.peek()` 不破坏 Principle 2 不变式（不变式针对 task-thread snapshot 的观测，而 task thread 不读 `drainEntries`，只读 `SpillFile.entries`）。结论：未违背两条铁则，但 lock 外的 peek 对应的注释（line 102-105）未在 SpillFile 处补 `drainEntries` 单线程读写约束声明，弱审计性。

## 总评

PASS — Principle 1（drain + Step 1 的 onRecoveredStateBuffer 在 lock 内；end-of-drain 在 lock 外；filter-off / toInputChannel 例外路径符合设计）与 Principle 2（offset 推进与 deliver 同块）在 `SpillFileReader.drain()` / `snapshotAndInsertBarriers()` 两个调用点严格满足，命名锁 + GuardedBy 注解到位，channel 内层锁顺序无反向。
