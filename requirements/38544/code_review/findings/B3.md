# B3. SpillFile segment 轮转 + append 单写者

## 设计期望
- `channelIOExecutor` 是唯一 writer；`SpillFile.append` 不允许加锁（一加锁即代表不再相信 single-writer 假设）。
- 单 segment 顺序 append；超 64MB 轮转；一条 entry 不跨 segment；单条 payload < segment 上限。
- `activeSegmentFor(length)` 必须在写入前预留够空间；`Entry(channelInfo, segmentIndex, offsetBeforeWrite, length)` 反映**写入前**状态；写入后才更新 `currentEnd`。
- 写入 FileChannel 不被 read 共用；drain 用 `FileChannel.open(path, READ)` 开独立 read handle。

- `flink-runtime/src/main/java/org/apache/flink/runtime/checkpoint/channel/SpillFileReader.java:100-139`（drain 侧 read 路径）

## 符合预期
- **single-writer 无锁**：`SpillFile.java` 内 `grep synchronized` 为空（已确认无 `synchronized`/`Lock`/`ReentrantLock`）。仅有 `AtomicInteger refCount`、`AtomicBoolean cleanedUp` 用于跨线程的 lifecycle 管理，不参与 append 路径（`SpillFile.java:169,176`）。注释 `SpillFile.java:51-53` 明确声明 single-writer invariant。
- **唯一 append 入口**：`FilteredBufferWriter.flush()` 内 `spillFile.append(currentChannel, payload)`（`FilteredBufferWriter.java:116`），是 main 代码中 `SpillFile.append` 的唯一调用点（grep 验证）。`flush` 仅由 `beginChannel` channel 切换路径（`FilteredBufferWriter.java:77-82`）、`requestBufferBlocking` buffer 满路径（`FilteredBufferWriter.java:97-101`）、`close` 残余 flush（`FilteredBufferWriter.java:134`）触发，全部在 channelIOExecutor 上调用。
- **Entry 反映写入前状态**：`SpillFile.java:217` 先取 `offsetBeforeWrite = active.currentEnd`，`SpillFile.java:219-228` 执行写入，`SpillFile.java:229` 写入后更新 `currentEnd`，`SpillFile.java:230` 用 `offsetBeforeWrite` 构造 `Entry`。顺序与设计期望一致。
- **`activeSegmentFor` 预留空间 + 不跨段**：`SpillFile.java:243-252` 在 `current.currentEnd + payloadLength > segmentSizeBytes` 时轮转新段；一次 append 全部 `length` 字节都写入同一 `active.channel`（`SpillFile.java:220-228` 的 `while (written < length)` 循环），不可能跨段。
- **read handle 独立**：drain 走 `SpillFileSegment.readBytesAt`（`SpillFile.java:109-128`），每次调用 `FileChannel.open(path, StandardOpenOption.READ)` 开新只读 handle（`SpillFile.java:113`），与 segment 自身写入 handle 不共用 position。
- **段轮转 fresh-segment 行为**：`SpillFile.java:254-267` 用 `CREATE_NEW` 避免覆盖；segmentIndex 取自 `segments.size()`，命名 `spill-segment-{index}.bin`；首条 entry 时 `segments.isEmpty()` 触发 lazy 创建（`SpillFile.java:244-246`）。
- **flush 后重置语义**：`FilteredBufferWriter.flush()` 写完后 `setReaderIndex(0)` + `setSize(0)` + `currentChannel = null`（`FilteredBufferWriter.java:117-119`）；`requestBufferBlocking` 自动 flush 时用 saved/restore 模式保留 channel tag（`FilteredBufferWriter.java:98-101`）。
- **drain 侧 per-segment 入队**：append 后 `active.drainEntries.add(entry)`（`SpillFile.java:235`）让 drain 按段 peek/poll，无需 re-grouping；同样依赖 single-writer 不加锁。

## 不符合预期
- `SpillFile.java:243-252` (`activeSegmentFor`)：无任何 `payloadLength <= segmentSizeBytes` 的防御性检查。若上游违反"network buffer << 64MiB"假设传入 `payloadLength > segmentSizeBytes` 的 payload，rotation 仍会打开新段并把超大 entry 写入，造成 segment 大小越界。设计文档（`unspiller.md` §2a "单 payload < segment 上限"）声明该约束依赖上游保证，但代码无 fail-loud guard。
- `SpillFile.java:258-263` (`openNewSegment`)：segment 写入 channel 用 `CREATE_NEW | WRITE | READ` 三个 flag 打开，包含 `READ` flag 但生产路径 `readBytesAt` 总是开独立 read handle（`SpillFile.java:113`），段自身的 `READ` 模式仅被 test-only `SpillFile.readBytes`（`SpillFile.java:408-430`）复用。`READ` flag 对 production 写入路径无意义，与设计"写入 FileChannel 不被 read 共用"语义有冗余偏离（虽然不构成正确性问题）。

## 总评
PASS WITH MINOR — single-writer 无锁、entry 写入前状态、段轮转、独立 read handle 全部到位；仅 `activeSegmentFor` 缺超大 payload 的 fail-loud guard 与 segment 写入 channel 多带的 `READ` flag 属于次要点。
