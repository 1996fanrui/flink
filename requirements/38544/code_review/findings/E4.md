# E4. allRecoveredBuffersDelivered 字段

## 设计期望

- `allRecoveredBuffersDelivered` 是 `LocalInputChannel` / `RemoteInputChannel` 上的新字段，类型 `boolean`，初值 `false`。
- 仅在 `finishReadRecoveredState()` 内由 `false` 翻转为 `true`，且整个生命周期内仅翻转一次；recovery 完成后不允许重置。
- 翻转必须在 channel internal monitor（Remote 是 `synchronized(receivedBuffers)`、Local 是 `synchronized(recoveredBuffers)`）内进行，借助 monitor 的 happens-before 让 consumer 看到正确值。
- 必须是 plain field，不允许声明为 `volatile`（happens-before 由 monitor 提供，`volatile` 反而模糊语义）。
- 语义上表达「producer（drain / 迁移路径）已不再写入 `recoveredBuffers`」，不表达 consumer 是否消费完；与 `recoveredBuffers.isEmpty()` 合起来构成 `inRecovery` predicate 和 `stateConsumedFuture` 完成条件。
- 全局只能有一处 `= true` 赋值（位于 `finishReadRecoveredState`），除字段声明外不应出现任何 `= false` 赋值。

## 符合预期

- 字段在两个物理 channel 上均声明为 `private boolean allRecoveredBuffersDelivered = false`，无 `volatile` 修饰（`LocalInputChannel.java:107`、`RemoteInputChannel.java:147`）。
- 全仓 `allRecoveredBuffersDelivered = true` 共两处：`LocalInputChannel.java:192`、`RemoteInputChannel.java:250`，且都位于各自 `finishReadRecoveredState()` 体内，符合「只在 finishReadRecoveredState 内翻转」的设计。
- 除字段初始化外没有 `allRecoveredBuffersDelivered = false` 赋值，符合「永不重置」要求（grep `allRecoveredBuffersDelivered\s*=` 仅命中初始化与上述两次 `= true`）。
- 翻转位点都在 channel internal monitor 内：Local 用 `synchronized (recoveredBuffers)`（`LocalInputChannel.java:191`），Remote 用 `synchronized (receivedBuffers)`（`RemoteInputChannel.java:249`），与 §1 lock 表一致。
- 所有读位点均在同一 monitor 内访问：
  - Local：`getNextBuffer` 的 `inRecovery` 计算（`LocalInputChannel.java:385-386`）、`wrapRecoveredBufferAsAvailability` 中 `else if (!allRecoveredBuffersDelivered)`（`LocalInputChannel.java:528-531`）、`checkpointStarted` 的 `inRecovery` 判定（`LocalInputChannel.java:204-205`）；
  - Remote：`getNextBuffer` 的 `inRecovery` 与 nextDataType 计算（`RemoteInputChannel.java:337-364`）、`checkpointStarted`（`RemoteInputChannel.java:857-858`）、`checkReadability` 中 `assert Thread.holdsLock(receivedBuffers)`（`RemoteInputChannel.java:1124-1125`）。
- 字段语义解释明确写在 javadoc：「producer-side completion only — the consumer may still have leftover buffers queued in `recoveredBuffers`」（`RecoverableInputChannel.java:60-62`），不与 consumer 完成混淆；`Full recovery completion` 显式表述为 `allRecoveredBuffersDelivered == true && recoveredBuffers.isEmpty()`（`LocalInputChannel.java:104-105`、`RemoteInputChannel.java:143-144`）。
- `SpillFileReader.drain()` 在 (D) 阶段在 lock 外对每个 channel 调用一次 `finishReadRecoveredState()`（`SpillFileReader.java:136-138`），与「producer 完成时翻转」语义吻合；end-of-drain 例外明确写在 javadoc（`RecoverableInputChannel.java:63-66`）。

## 不符合预期

- `LocalInputChannel.java:107` 字段声明缺少 `@GuardedBy("recoveredBuffers")` 注解；同文件同语义的 `RemoteInputChannel.java:146` 标注了 `@GuardedBy("receivedBuffers")`，注解一致性缺失（仅文档型，不影响运行时；同时影响 `recoveredBuffers` 字段 `LocalInputChannel.java:94`，但 E4 范围限于 flag 字段本身）。

## 总评

PASS WITH MINOR — 字段的初值、翻转点、永不重置、非 volatile、monitor 内访问、producer-only 语义全部满足；唯一缺口是 `LocalInputChannel.java:107` 漏标 `@GuardedBy` 注解，属文档型瑕疵。
