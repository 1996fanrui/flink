# C2. Drain 4 步结构（(A)(B)(C)(D)）

## 设计期望

- (A) `requestBufferBlocking` 在 `SpillFileReader.lock` **外**调用；buffer pool park 不能进 lock，否则 buffer-pool 抖动会卡 checkpoint Step 1。
- (B) `seg.readBytesAt(...)` 在 lock **外**对当前迭代私有的 `buf` 进行同步 IO；`buf` 此时未对其它线程可见。
- (C) **同一** `synchronized (lock)` block 内**且仅**执行四个动作：
  1. `ch.onRecoveredStateBuffer(buf)`
  2. `seg.pollNextEntry()`
  3. `currentSegmentIndex = seg.segmentIndex`
  4. `currentOffset = e.offset + e.length`
- (D) drain 主循环结束后，对 `allChannels` 每一个 channel 调用 `finishReadRecoveredState()`，在 lock **外**（end-of-drain 例外，无新 buffer 写入故 Principle 1 不适用）。
- 异常路径：(A) 申请到的 `buf` 若在 (B) / (C) 抛错必须 recycle，避免泄漏。
- (D) 必须对 `allChannels` 每个元素调用一次（不能跳过未收到 entry 的 channel）。

## 符合预期

- `SpillFileReader.java:115`：(A) `bufferRequester.requestBufferBlocking(e.channelInfo)` 位于 `synchronized` 之外。
- `SpillFileReader.java:119-122`：(B) 数组分配、`seg.readBytesAt`、`MemorySegment.put`、`buf.setSize` 全部在 lock 外，对私有 `buf` 操作。
- `SpillFileReader.java:126-131`：(C) `synchronized (lock)` 单一 block 内严格包含四个动作（`onRecoveredStateBuffer` → `pollNextEntry` → `currentSegmentIndex=` → `currentOffset=`），无多余慢操作。
- `SpillFileReader.java:62-68`：`lock` 为 `private final Object`（非 `this`），且 `currentSegmentIndex`/`currentOffset` 标注 `@GuardedBy("lock")`。
- `SpillFileReader.java:136-138`：(D) end-of-drain 对 `allChannels` 全集逐个 `finishReadRecoveredState()`，在 lock 外执行，符合 Principle 1 例外。
- `SpillFileReader.java:108-111`：drain 找不到物理 channel 时抛 `IllegalStateException`，fail-loud。

## 不符合预期

- `flink-runtime/src/main/java/org/apache/flink/runtime/checkpoint/channel/SpillFileReader.java:115-131`：(A) 申请到的 `buf` 在 (B) (`new byte[e.length]` OOM、`readBytesAt` IOException、`MemorySegment.put` 越界、`buf.setSize` 异常) 或 (C) (`onRecoveredStateBuffer` 抛错) 抛出时未被 recycle，直接随栈帧丢失，造成 NetworkBuffer 泄漏；drain 主体内没有 try / finally 兜底回收。这违反了 C2 checklist 中"申请到的 buf 在 (B)/(C) 抛错时必须 recycle"的要求。
- `flink-runtime/src/main/java/org/apache/flink/runtime/checkpoint/channel/SpillFileReader.java:136-138`：(D) `finishReadRecoveredState` 循环没有 per-channel try/catch 包裹，单个 channel 抛 `IOException` 会中断后续 channel 的调用，导致剩余 channel 的 `allRecoveredBuffersDelivered` 永远不翻转、`stateConsumedFuture` 不完成。虽然此项主要落在 C3，但 (D) 在 C2 范围内对"对 allChannels 每个元素都调一次"的承诺存在缺口。
- `flink-runtime/src/main/java/org/apache/flink/runtime/checkpoint/channel/SpillFileReader.java:99-139`：drain 整体没有任何 try/finally，如果迭代中途抛错（包括 (A) interrupt、(B) IO 错误等），未消费的 entry 在 SpillFile 中保留正常，但已申请的 buffer 与"剩余 channel 未收到 finishReadRecoveredState"问题叠加，符合 C2 中"异常路径"项的不完整。

## 总评

PASS WITH MINOR — (A)(B)(C)(D) 主线时序与 lock 边界与设计一致，但 (B)/(C) 阶段抛错时 buffer 未 recycle、(D) 阶段单 channel 抛错会中断对其它 channel 的调用，属于 C2 异常路径覆盖不全。
