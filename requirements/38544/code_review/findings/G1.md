# G1. 防御性：fail-loud not silent

## 设计期望

`coordination.md` §7 与 checklist G1 要求：设计上"必然可达 / 可获取 / 必然存在"的对象，在实现里必须 throw on negative，禁止 silent skip / silent default / 兜底空返回。具体定锚点：

- `channel.checkpointStarted` in-recovery 分支必须找到 cpId-matched `RecoveryCheckpointBarrier`，走到队尾无匹配 = bug，必须 throw（不可 `assert`，因 `assert` 默认 off）。
- `SpillFileReader.drain` 中 `channelByInfo.get(e.channelInfo)` 找不到必须 throw。
- `ChannelStateFilteringHandler.filterAndRewrite` 找 `VirtualChannel` 找不到必须 throw（master 既有）。
- `RecoveredChannelStateHandler.recover` 的 `getMappedChannels` 不能返回 null。
- buffer pool 满时绝不回退到 heap fallback；fail-loud → park。
- 任意 `catch (Exception ignored) {}` 一律可疑。

## 符合预期

- `SpillFileReader.drain` L107-111：`channelByInfo.get` 命中 null 立即 throw `IllegalStateException`，匹配 G1 定锚点。
- `RecoveredChannelBufferRequester.requestBufferBlocking` L47-50：source channel 不存在直接 throw。
- `ChannelStateFilteringHandler.GateFilterHandler.filterAndRewrite` L307-314：VirtualChannel 缺失抛 `IllegalStateException`，附带 known channels 帮助排查。
- `RecoveredChannelStateHandler.calculateMapping` L388-399：`@Nonnull` + `checkState(mappedIndexes.length == 1, …)` + `getChannel` 内部对非 `RecoveredInputChannel` 抛错，保证 `getMappedChannels` 不可能返回 null。
- `ResultSubpartitionDistributor.calculateMapping` L60-66：mapping 为空时 throw。
- `RecoveredInputChannel.requestBufferBlocking` L345-353：仅 `bufferManager.requestBufferBlocking()` 一条路；不再有 master 的 heap fallback，buffer 池耗尽就 park（A1 已确认 grep `allocateUnpooledSegment` 在 filter 路径不复存在）。
- `RecoveredInputChannel.checkpointStarted` L356-358：在恢复期收到 checkpoint barrier 直接抛 `CHECKPOINT_DECLINED_TASK_NOT_READY`。
- `SpillFile.append` L201-205：`closed` 时立即 throw `IllegalStateException`，防御性写入禁止。
- `SpillFile.readBytes` / `SpillFileSegment.readBytesAt` L109-127、L408-429：EOF 直接 throw `IOException`，禁止短读静默吞掉。
- `ChannelStateWriterImpl.addInputDataFromSpill` L240-273：enqueue 失败时 `result.fail(e)` 后 rethrow，不静默忽略。
- `ChannelState.onCheckpointStartedForAllInputs` L158-184：dispatcher 异常路径关 snap 时仅 `LOG.warn(... suppressed)`，原因是主异常正在传播，符合"二次异常 suppressed"的常规模式。

## 不符合预期

- `flink-runtime/src/main/java/org/apache/flink/runtime/io/network/partition/consumer/LocalInputChannel.java:238-253`：`collectPreRecoveryBarrier` walk 到队尾未命中 cpId-matched barrier 时直接 `return retained;`，无任何 throw。违反 `coordination.md` §3.3 与 checklist F4/G1 明文："End-of-queue without a match is a bug — throw, don't silently return an empty retained list"。Step 1 既然保证已插入 barrier，找不到只能是 lost-barrier 这类一致性 bug，必须 fail-loud。
- `flink-runtime/src/main/java/org/apache/flink/runtime/io/network/partition/consumer/RemoteInputChannel.java:904-919`：`collectPreRecoveryBarrier` 同样在 walk 到队尾未命中时 `return retained;`，违反同一条规则。两个 channel 的 bug 同源。
- `flink-runtime/src/main/java/org/apache/flink/runtime/checkpoint/channel/FilteredBufferWriter.java:96`、`flink-runtime/src/main/java/org/apache/flink/runtime/checkpoint/channel/FilteredBufferWriter.java:114`：`assert currentChannel != null` 用 Java `assert`，默认 JVM 关闭 assertion 时静默通过，违反 "必须 throw 不能用 assert" 原则。`requestBufferBlocking` / `flush` 的 `currentChannel` 不变式是关键安全点（一旦丢失，"一个 entry 只装一个 channel" 不变式直接失效，A2 在历史 round 中已被 hit），不能依赖默认关闭的 assert。
- `flink-runtime/src/main/java/org/apache/flink/runtime/io/network/partition/consumer/LocalInputChannel.java:211-212`、`flink-runtime/src/main/java/org/apache/flink/runtime/io/network/partition/consumer/RemoteInputChannel.java:863-864`、`flink-runtime/src/main/java/org/apache/flink/runtime/io/network/partition/consumer/RemoteInputChannel.java:869-870`：互斥分支的 defensive 检查用 `assert recoveredBuffers.isEmpty()` / `assert receivedBuffersHasNoLiveDataBuffer()`。设计 `input_channel.md` §3.8 / `coordination.md` §3.3 伪码确实写的是 `assert`，但 checklist F4/G1 明文要求 "必须 throw 不能用 assert（assert 是 default-off 的）"。同样的不变式违反在生产中会被静默吞掉，需要 reviewer 仲裁：要么改设计文档，要么改实现。
- `flink-runtime/src/main/java/org/apache/flink/runtime/checkpoint/channel/ChannelStateCheckpointWriter.java:177-178`：`if (isDone()) { try { chunks.close(); } catch (Exception ignored) {} }` 静默吞 close 异常。`chunks.close()` 会触发 `DiskSnapshot.close()` 释放 SpillFile ref-count；这里 swallow 会让 SpillFile 释放失败被吞，事后无 log，故障定位困难。

## 总评

FAIL — `LocalInputChannel.collectPreRecoveryBarrier` / `RemoteInputChannel.collectPreRecoveryBarrier` 在找不到 cpId-matched barrier 时静默返回，与 G1/F4 设计明文相左；FilteredBufferWriter 等多处仍以默认关闭的 `assert` 守护关键不变式，无法在生产保留 fail-loud。
