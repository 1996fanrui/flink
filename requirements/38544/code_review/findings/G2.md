# G2 — 异常路径资源不能 leak

## 设计期望

drain / filter / handoff / 3-step / writer 任何路径抛异常时已 acquire 的资源（buffer、pool exclusive buffer、SpillFile refCount、temp 目录、retain 的 Buffer）必须释放；任何 future / 状态机不能因异常被永久挂起（特别是 `bufferFilteringCompleteFuture` / `stateConsumedFuture`）。

## 符合预期

- `StreamTask` 三条失败路径（filter throw / allConverted err / handoffSpillReaderToDrain throw）都显式释放 producer-side SpillFile grant + completeExceptionally(drainHandoff)（`StreamTask.java:923-936,1015-1031,1086-1103`）。
- `SpillFileReader.close()` 用 try/finally 保证 `spillFile.release()` 即便 `releaseExclusiveBuffers` 抛错也运行（`SpillFileReader.java:181-187`）。
- drain 主循环 fail 时 StreamTask runnable finally 调用 `spillReader.close()` 释放 drain grant（`StreamTask.java:961-967`）。
- `ChannelState.onCheckpointStartedForAllInputs` 用 finally 在 Step 1/2 抛错时调用 `snap.close()` 释放 Step 3 grant（`ChannelState.java:172-183`）。
- `ChannelStateWriterImpl.addInputDataFromSpill` 空 snap 立即 close 释放 grant；enqueue 失败时 cancel 走 discardAction 关闭 iterator（`ChannelStateWriterImpl.java:245-272`，`ChannelStateWriteRequest.java:269-281,378-383`）。
- `ChannelStateCheckpointWriter.writeInputFromSpill` 用 try/finally 在写入过程中抛错时仍关闭 chunks（`ChannelStateCheckpointWriter.java:199-201`）。
- `SpillFile.release()` 与 `close()` 共用 `cleanedUp` CAS，重复 release/close 不会重复删段（`SpillFile.java:285-292,300-309`）。
- `ChannelStateFilteringHandler.filterAndRewrite` 用 try/catch 在 deserializer 抛错时回收 sourceBuffer / currentBuffer / 已生成的 resultBuffers（`ChannelStateFilteringHandler.java:347-362`）。

## 不符合预期

- `RecoveredChannelStateHandler.java:294-308`：`spillFile.acquire()` 在 line 294 完成后，line 296 `channel.requestBufferBlocking()` 若抛 InterruptedException / IOException，本地 `spillFile` 引用立即超出作用域，且 `spillFileWriter` 仍为 `null`。后续 handler.close 走不到 `getProducedSpillFile()`，StreamTask 失败路径 `reader.getProducedSpillFile()` 返回 `null` → producer grant 永久未释放，segments + temp 目录无法清理。
- `RecoveredChannelStateHandler.java:287, SpillFile.java:315-340`：`resolveSpillBaseDir` 通过 `Files.createTempDirectory(...)` 创建 `flink-channel-spill-XXXX` 目录，但 `SpillFile.deleteAllSegments` 只删 `seg.path`（line 328），从未删除 `baseDir` 本身。即使 happy path 跑完，每次 task recover 都会在 tmp 留一个空目录。
- `RecoveredChannelStateHandler.java:347-373`：`close()` 没有 try/finally 串联多个清理动作。若 `spillFileWriter.close()`（line 354，含 `flush` → `spillFile.append`）抛 IOException，后续 `filterOutputPooledBuffer.recycleBuffer()`（line 361）、`inputGate.finishReadRecoveredState()`（line 366）、`preFilterSegment.free()`（line 369）全部不执行 → exclusive pool buffer leak、preFilterSegment unpooled heap segment leak，且 `bufferFilteringCompleteFuture` 永不完成，task hang。
- `SpillFileReader.java:115-131`：drain 循环 (A) 后获取的 `buf` 没有任何 try/finally 守护。`seg.readBytesAt`（line 120，IOException）或后续 `buf.getMemorySegment().put(...)`（line 121，可能抛 IndexOutOfBoundsException 当 `e.length` 与 buf 容量不匹配）抛错时 `buf` 不会被 recycle → pool buffer leak（违反 checklist C2/G2 “(B)/(C) 抛错时 buf 必须 recycle”）。
- `SpillFileReader.java:100-138`：整个 drain 主循环没有 try/finally 兜底 (D) 的 `finishReadRecoveredState`。中途抛错（(A) interrupt / (B) IO / new byte[e.length] OOM）时不会对所有 channel 调用 `finishReadRecoveredState`，对应 channel 的 `allRecoveredBuffersDelivered` 永远停在 `false`，`stateConsumedFuture` 永不完成 → 下游 mailbox suspend trigger 永远 hang（同时违反 checklist C3）。
- `SpillFileReader.java:147-169`：`snapshotAndInsertBarriers` 在 line 163 `spillFile.acquire()` 之后于 line 165-168 调用 `EventSerializer.toBuffer(new RecoveryCheckpointBarrier(checkpointId), false)`（declared `throws IOException`），若中途抛错，DiskSnapshot 构造（line 171-172）从未执行，acquire 的 grant 没有任何持有者负责 release。`ChannelState.onCheckpointStartedForAllInputs` 的 finally 检查的是 `snap != null`，但调用本身抛错时 `snap` 仍是 `null` → grant 永久泄漏。已部分插入 channel 的 barrier 也作为 Buffer 滞留在 `recoveredBuffers` 中。
- `RemoteInputChannel.java:904-919` / `LocalInputChannel.java:238-253`：`collectPreRecoveryBarrier` 走到一半若 `isRecoveryCheckpointBarrier`（`EventSerializer.fromBuffer`，throws IOException）抛错，已 `b.retainBuffer()` 加入 `retained` 的 Buffers 没有被 recycle；异常被 wrap 成 CheckpointException 抛出，retain 计数永久挂账，pool buffer leak。
- `RecoveredChannelBufferRequester.java:55-59`：`releaseExclusiveBuffers` 顺序 for-loop 调 `ch.releaseAllResources()`，若任一 channel 抛 IOException，其后的 channel 不会被释放（exclusive buffer 累计 leak）。SpillFileReader.close 的 finally 仅守护 spillFile.release，不补齐剩余 channel 的释放。

## 总评

FAIL — 多条核心异常路径（drain 主循环未守护 buf 与 `finishReadRecoveredState`、`snapshotAndInsertBarriers` acquire 后 `toBuffer` 抛错、`ensureSpillFileWriter` acquire 后 buffer 申请抛错、handler.close 缺乏 try/finally）都会泄漏 SpillFile grant / pool buffer / 未删 temp 目录或挂起 stateConsumedFuture。
