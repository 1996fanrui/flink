Phase 3 · 11.2 weeks against a 2-week estimate

The hard part was consistency, not volume.

01
Two media, one snapshot
Buffers still in memory and data already spilled to disk have to be captured as one consistent point.
02
A new barrier type
Introduced so that point is well defined while recovery is still running.
03
Shuffle × snapshot
Exactly-once has to hold across every upstream/downstream interaction during recovery.
04
Priority events stay fast
Delay the unaligned barrier and checkpoints get slow — which is the very thing this feature exists to fix.

The 2-week estimate was set in October 2025, before any spilling design existed. Redesigning it later took two weeks of discussion alone.
