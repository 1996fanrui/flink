# 用户需求文档

## 需求偏离
无

## 核心需求

### 1. 测试执行Skill功能
创建一个Skill工具，用于自动化运行Flink测试并生成分析报告。

### 2. 工作流程要求

#### 2.1 环境准备
- 提交本地未提交代码
- 在 `/tmp/claude-tmp` 目录下创建独立worktree
- worktree子目录名必须包含时间戳或UUID后缀，确保唯一性
- 使用 `rui_tools/build_with_specific_version.sh` 编译项目

#### 2.2 测试配置
- 支持运行多个测试类或方法
- 支持口语化描述测试需求（通过agent调研提供测试列表）
- 支持自定义循环次数（默认100次）

#### 2.3 错误处理
- 自动检测checkstyle错误
- 尝试自动修复简单的checkstyle问题
- 无法修复时停止并报告

### 3. 结果分析要求

#### 3.1 双粒度报告
- **粗粒度**：统计循环执行的整体成功率（100次循环中有多少次完全成功）
- **细粒度**：精确到test case + 参数化级别的成功/失败统计
- 细粒度部分必须先给出总体数据概览：总执行次数（test case数 × 迭代轮数）、总成功数、总失败数及占比
- 细粒度表格只列出失败的test case，成功的不逐条列出（只在总数中体现）

#### 3.2 失败分析
- 列出所有失败的test case（包含参数化信息）
- 统计每个失败case的失败次数
- 提供快速定位失败测试的awk命令：
  ```bash
  awk '/\[ERROR\] Errors:/{if(!found) print "---"; found=1} found{print FILENAME": "$0} /Tests run:/{if(found) found=0}' ./202*.log
  ```

#### 3.3 测试识别规范
- 按照Flink的TestLogger规范识别测试开始和结束
- 测试开始标记：`Test xxx is running`
- 测试成功标记：`Test xxx successfully run`
- 测试失败标记：`Test xxx failed with`

#### 3.4 失败日志拆分
- 将每个失败的test case（参数化粒度）的日志从完整日志中拆分出来，生成独立的小文件
- 拆分范围：从测试开始标记到测试结束标记之间的完整日志
- 文件命名：以test case名称 + 参数命名，且标注来源（原始日志文件名）
- 创建独立子目录存放拆分后的日志
- 所有包含失败的原始日志必须完整保留

#### 3.5 报告拆分
- 输出两份报告：**摘要报告**（report.md）和**失败详情报告**（failure_details.md）
- 摘要报告包含：汇总统计、commit信息、测试请求信息、粗粒度和细粒度统计（仅失败项）、awk命令
- 失败详情报告包含：每个失败test case的完整stack trace和split log路径
- commit信息和测试请求信息直接写入报告，不生成单独的commit_info.txt和test_request.txt文件

#### 3.6 日志归档和报告持久化
- worktree删除之前，将日志和报告移到主仓库的 `log/` 目录下
- `log/` 下创建带前缀和时间戳的独立目录，格式为 `flink-test-analyzer_YYYYMMDD_HHmmss`，前缀标识报告来源
- 归档目录下保留：
  - 所有包含失败的原始日志文件
  - 拆分后的失败test case日志子目录
  - 摘要报告和失败详情报告

### 4. 技术架构要求

#### 4.1 Agent架构
- 主协调agent仅负责调度，不执行具体工作
- 每个步骤至少由两个sub agent执行：一个执行agent + 一个独立的验证agent
- 验证agent不通过时，重新运行执行agent（不更新文档），直到验证通过后再进入下一步
- 交付质量优先于效率，多启动验证agent没有关系

#### 4.2 脚本实现
- 日志解析必须用脚本实现（不用大模型）
- 混合使用Shell和Python：Shell负责调用，Python负责解析分析
- 将解析命令封装成独立脚本保存在skill目录

### 5. 资源管理
- 测试完成后必须清理worktree
- 清理前先将日志和报告归档到主仓库
- 提供自动清理策略
- 确保不会产生资源泄露

### 6. 脚本复用策略
- build_with_specific_version.sh 如无问题直接复用
- 其他脚本提取到skill目录独立维护
- 保持脚本通用化，支持参数配置

### 7. 代码语言要求
- 所有代码和skill文件不允许出现中文，全部使用英文（包括注释、日志输出、报告模板等）

### 8. 文件组织要求
- 所有新增的代码和文档都放到项目的 `.claude/skills/flink-test-analyzer/` 目录下
- Skill名称为 `flink-test-analyzer`

### 9. 时间戳格式规范
- 所有用到时间的地方，日期和时分秒之间必须加下划线分隔，格式为 `YYYYMMDD_HHmmss`

### 10. 执行前预期生成与验证
- 在所有步骤运行之前，先生成预期内容（如测试类包含多少个test method、多少个参数化组合、预期运行的测试总数）
- 每阶段完成后，独立验证agent对比实际结果与预期，确保无遗漏
- 可通过代码/命令技术手段提前获取准确的测试用例数量信息
