## Commit 信息

- Message: [FLINK-38543][checkpoint] Change overall UC restore process for checkpoint during recovery

## 改动概述

本次改动的核心目标是：当 "unaligned checkpoint during recovery" 功能开启时，允许 Task 更早地进入 RUNNING 状态（从而更早触发 checkpoint），而不必等到所有恢复状态被完全消费。

### 代码结构与文件职责

**核心改动文件：**

1. **`IndexedInputGate.java`** -- 抽象基类，新增 `setUnalignedDuringRecoveryEnabled(boolean)` 抽象方法，用于将配置标志传递到 input gate 层。

2. **`SingleInputGate.java`** (本次 commit 未修改，但是关键依赖) -- 实际存储 `isUnalignedDuringRecoveryEnabled` volatile 字段，提供 `setUnalignedDuringRecoveryEnabled()` 和 `isUnalignedDuringRecoveryEnabled()` 方法。同时提供 `getBufferFilteringCompleteFuture()` 聚合所有 channel 的 bufferFilteringCompleteFuture。

3. **`RecoveredInputChannel.java`** (本次 commit 未修改，但是关键依赖) -- 包含 `bufferFilteringCompleteFuture` 字段。在 `finishReadRecoveredState()` 中根据 `inputGate.isUnalignedDuringRecoveryEnabled()` 决定是否 complete 该 future。在 `toInputChannel()` 中根据同一标志决定检查哪个 future。

4. **`StreamTask.java`** -- 恢复流程的编排入口。改动了 `restoreStateAndGates()` 方法：
   - 在启动异步读取任务前，将配置标志通过 `setUnalignedDuringRecoveryEnabled()` 设置到所有 input gate
   - 根据标志选择使用 `bufferFilteringCompleteFuture` 或 `stateConsumedFuture` 来驱动 RUNNING 状态转换和 `requestPartitions` 调用

5. **`InputGateWithMetrics.java`** -- `IndexedInputGate` 的装饰器，简单委托 `setUnalignedDuringRecoveryEnabled()` 到内部 input gate。

**测试文件：**

6. **`RecoveredInputChannelTest.java`** -- 核心测试，验证 config 开启/关闭时 `bufferFilteringCompleteFuture` 和 `stateConsumedFuture` 的完成时机，以及 `toInputChannel()` 的前置条件检查。

7. **`SingleInputGateTest.java`** -- 新增 `testBufferFilteringCompleteFutureAggregation` 测试，验证 `SingleInputGate` 级别 future 聚合的正确性。

8. **`SingleInputGateBuilder.java`** -- 测试 builder，新增 `setUnalignedDuringRecoveryEnabled` 支持。

9. **`MockIndexedInputGate.java` / `MockInputGate.java` / `AlignedCheckpointsMassiveRandomTest.java`** -- Mock 类和测试类，添加空实现以满足抽象方法要求。

**文件间关系：**

```
StreamTask.restoreStateAndGates()
  |-- 读取配置 CheckpointingOptions.isUnalignedDuringRecoveryEnabled()
  |-- 设置 IndexedInputGate.setUnalignedDuringRecoveryEnabled()
  |      |-- InputGateWithMetrics 委托给内部 SingleInputGate
  |      \-- SingleInputGate 存储 volatile 字段
  |-- 提交异步任务到 channelIOExecutor
  |      \-- reader.readInputData() -> RecoveredInputChannel.finishReadRecoveredState()
  |             \-- 根据 inputGate.isUnalignedDuringRecoveryEnabled() 决定是否 complete bufferFilteringCompleteFuture
  \-- 根据标志选择 future 驱动 RUNNING 状态转换
```

### 关键规则验证

当 `isUnalignedDuringRecoveryEnabled` 为 false 时：
- `setUnalignedDuringRecoveryEnabled(false)` 被调用但不影响任何行为
- `StreamTask` 中 `useBufferFilteringFuture` 为 false，选择 `getStateConsumedFuture()`，与原始逻辑完全一致
- `RecoveredInputChannel.finishReadRecoveredState()` 不 complete `bufferFilteringCompleteFuture`
- `RecoveredInputChannel.toInputChannel()` 检查 `stateConsumedFuture`，与原始逻辑一致

结论：当功能关闭时，原有行为不受影响。

## 备注

1. **线程安全分析**：`SingleInputGate.isUnalignedDuringRecoveryEnabled` 字段是 `volatile` 的，确保了跨线程可见性。`StreamTask` 中在主线程设置标志后才通过 `channelIOExecutor.execute()` 提交异步任务，happens-before 关系正确。`RecoveredInputChannel.finishReadRecoveredState()` 在 channelIOExecutor 线程上执行，读取到的 `isUnalignedDuringRecoveryEnabled` 值是正确的。

2. **原有行为兼容性**：当 `isUnalignedDuringRecoveryEnabled` 为 false 时，`StreamTask` 选择 `getStateConsumedFuture()` 路径，`RecoveredInputChannel.finishReadRecoveredState()` 不 complete `bufferFilteringCompleteFuture`，`toInputChannel()` 检查 `stateConsumedFuture`。所有行为与改动前完全一致，不影响已有功能。

3. **改动范围合理性**：本次改动仅修改了恢复流程中 RUNNING 状态转换所依赖的 future 选择逻辑，改动范围清晰且集中。新增的 `setUnalignedDuringRecoveryEnabled` 方法通过 `IndexedInputGate` 抽象层传播配置，设计合理。

4. **测试覆盖**：测试覆盖了 channel 级别和 gate 级别的行为，且分别验证了 config 开启和关闭两种场景。`TestableRecoveredInputChannel` 的引入使得可以测试 `toInputChannel()` 的成功路径。整体测试质量良好。
