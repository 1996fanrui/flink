## Commit 信息

- Message: [FLINK-38930][checkpoint] Filtering record before processing without spilling strategy

## 改动概述

本次提交实现了在 channel-state-unspilling 线程中对恢复的 channel state buffer 进行记录过滤的核心机制。当 `isUnalignedDuringRecoveryEnabled` 为 true 时，过滤在 unspilling 线程中提前完成，避免了在 Task 主线程中使用 `RescalingStreamTaskNetworkInput` 进行冗余的 demultiplexing/filtering。

### 代码结构与文件职责

1. **`ChannelStateFilteringHandler.java`** (新增, 496 行): 核心过滤处理器。采用分层设计，外层按 gate 索引管理 `GateFilterHandler`，每个 `GateFilterHandler` 内部按 `SubtaskConnectionDescriptor` 管理 `VirtualChannel`。负责将 buffer 中的记录反序列化、过滤、再序列化为新 buffer。

2. **`RecordFilterContext.java`** (新增, 227 行): 过滤上下文，封装了过滤所需的所有信息：输入配置 (`InputFilterConfig`)、rescaling 描述符、subtask 索引、max parallelism、临时目录等。通过 `StreamTask.createRecordFilterContext()` 构建。

3. **`VirtualChannelRecordFilterFactory.java`** (新增, 123 行): 工厂类，负责从 `RecordFilterContext` 创建 `RecordFilter` 实例。对 ambiguous channel 创建基于 partitioner 的过滤器，对非 ambiguous channel 创建 pass-through 过滤器。

4. **`RecoveredChannelStateHandler.java`** (修改): `InputChannelRecoveredStateHandler` 增加了可选的 `ChannelStateFilteringHandler` 字段。当 handler 非空时走 `recoverWithFiltering` 路径，否则走原有的 `recoverWithoutFiltering` 路径。

5. **`SequentialChannelStateReader.java` / `SequentialChannelStateReaderImpl.java`** (修改): `readInputData` 方法签名增加 `RecordFilterContext` 参数。实现中根据 `isUnalignedDuringRecoveryEnabled` 决定是否创建 `ChannelStateFilteringHandler`。

6. **`StreamTaskNetworkInputFactory.java`** (修改): 增加 `unalignedDuringRecoveryEnabled` 参数。当该参数为 true 时，即使存在 rescaling 也使用 `StreamTaskNetworkInput`（因为过滤已在 unspilling 线程完成）。

7. **`StreamTask.java`** (修改): 新增 `createRecordFilterContext()` 方法，从 `StreamConfig` 和 `Environment` 中收集构建 `RecordFilterContext` 所需的全部信息。

8. **`OneInputStreamTask.java` / `StreamTwoInputProcessorFactory.java` / `StreamMultipleInputProcessorFactory.java`** (修改): 传递 `unalignedDuringRecoveryEnabled` 参数到 `StreamTaskNetworkInputFactory.create()`。

9. **测试文件** (修改): `SequentialChannelStateReaderImplTest` 和 `ChannelPersistenceITCase` 适配新的 `readInputData` 签名，传入 `RecordFilterContext.disabled()`。

### 文件间关系

- `StreamTask` 创建 `RecordFilterContext` 并传给 `SequentialChannelStateReaderImpl.readInputData()`
- `SequentialChannelStateReaderImpl` 使用 `RecordFilterContext` 创建 `ChannelStateFilteringHandler`，然后将其传给 `InputChannelRecoveredStateHandler`
- `ChannelStateFilteringHandler` 使用 `VirtualChannelRecordFilterFactory` 创建每个虚拟通道的 `RecordFilter`
- `InputChannelRecoveredStateHandler.recover()` 在恢复每个 buffer 时调用 `ChannelStateFilteringHandler.filterAndRewrite()`
- 同时 `StreamTaskNetworkInputFactory` 根据 `unalignedDuringRecoveryEnabled` 决定使用 `StreamTaskNetworkInput` 还是 `RescalingStreamTaskNetworkInput`

## 备注

1. **向后兼容性**: 当 `isUnalignedDuringRecoveryEnabled` 为 false 时，代码通过 `RecordFilterContext.disabled()` 或条件判断确保走原有逻辑路径。`SequentialChannelStateReaderImpl` 中 `filteringHandler` 为 null 时传给 `InputChannelRecoveredStateHandler` 的三参数构造函数等同于原来的两参数构造函数行为。`StreamTaskNetworkInputFactory` 在 `unalignedDuringRecoveryEnabled` 为 false 时与原逻辑一致。向后兼容性保障是充分的。

2. **线程安全**: `ChannelStateFilteringHandler` 和 `GateFilterHandler` 中的字段（`outputSerializer`、`lengthBuffer`、`deserializationDelegate`）是非线程安全的可变状态。但由于这些组件只在 channel-state-unspilling 线程中使用，且一个 handler 在一个时间只被一个线程调用，因此不存在并发问题。

3. **跨模块依赖**: `ChannelStateFilteringHandler` 位于 `flink-runtime` 的 `checkpoint.channel` 包，但依赖了 `flink-streaming-java` 的 `recovery` 包中的类（`RecordFilter`、`VirtualChannel`、`RecordFilterContext` 等）。由于 `flink-streaming-java` 的类实际上位于 `flink-runtime` 模块内的 `streaming` 包中，因此不存在模块依赖循环问题。
