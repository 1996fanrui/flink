## 第一部分：改动概述与代码结构

### 改动内容

本次改动修复了一个 recovery 阶段的竞态条件 bug。改动仅涉及一个文件：

- **`flink-runtime/src/main/java/org/apache/flink/streaming/runtime/tasks/StreamTask.java`** (8 行新增，2 行删除)

### 问题背景

`StreamTask` 在 `restoreInternal()` 方法中调用 `restoreStateAndGates()` 来恢复 input gate 的状态。恢复完成后，通过 mailbox 机制来终止恢复阶段的 mailbox 循环。具体流程如下：

1. `restoreStateAndGates()` 返回一个 `CompletableFuture<Void>`（即 `allGatesRecoveredFuture`）
2. `mailboxProcessor.runMailboxLoop()` 运行 mailbox 循环，等待所有 gate 恢复
3. 恢复完成后，`suspend()` 被调用，向 mailbox 发送一封 poison mail 来终止循环
4. `runMailboxLoop()` 退出后，通过 `checkState(allGatesRecoveredFuture.isDone(), ...)` 断言恢复已完成

### 关键代码关系

- `StreamTask.restoreInternal()`（第 829-843 行）：调用 `restoreStateAndGates()` 获得 future，然后运行 mailbox 循环，循环退出后断言 future 已完成
- `StreamTask.restoreStateAndGates()`（第 859-937 行）：执行异步恢复，组合所有 input gate 的恢复 future，恢复完成后调用 `mailboxProcessor.suspend()` 终止 mailbox 循环
- `MailboxProcessor.suspend()`（第 238-240 行）：通过 `sendPoisonMail()` 向 mailbox 队列发送一封 poison mail，设置 `suspended = true`
- `MailboxProcessor.runMailboxLoop()`（第 214-235 行）：循环处理 mail，当 `suspended` 变为 true 时退出循环

### Bug 的根因

修复前的代码：
```java
return CompletableFuture.allOf(recoveredFutures.toArray(new CompletableFuture[0]))
        .thenRun(mailboxProcessor::suspend);
```

`thenRun()` 会返回一个新的 `CompletableFuture`，这个新 future 在 callback（即 `suspend()`）执行完毕后才会 complete。问题在于：

1. `suspend()` 运行在异步线程上，它通过 `sendPoisonMail()` 向 mailbox 队列投递 poison mail
2. Mailbox 线程处理 poison mail，设置 `suspended = true`，mailbox 循环退出
3. 但此时 `suspend()` 方法本身可能还没有从 `sendPoisonMail()` 返回（因为 `runExclusively` 需要获取锁）
4. 因此 `thenRun` 返回的 future 可能尚未 complete，导致 `allGatesRecoveredFuture.isDone()` 返回 false
5. 触发 `checkState` 断言失败，抛出 "Mailbox loop interrupted before recovery was finished."

### 修复方案

修复后的代码将 `allOf` 的结果 future 和 `thenRun` 的链式调用解耦，返回 `allOf` 本身的 future 而非 `thenRun` 产生的新 future：

```java
CompletableFuture<Void> allRecoveredFuture =
        CompletableFuture.allOf(recoveredFutures.toArray(new CompletableFuture[0]));
allRecoveredFuture.thenRun(mailboxProcessor::suspend);
return allRecoveredFuture;
```

这样，`allGatesRecoveredFuture.isDone()` 只要所有 input gate 恢复完成就为 true，不再受 `suspend()` 方法执行时机的影响。

## Review 结论

**通过**

本次改动正确修复了 `CompletableFuture.thenRun()` 返回新 future 导致的竞态条件问题。修复方案简洁且符合逻辑：返回 `allOf` 的 future 而非 `thenRun` 产生的新 future，确保 `isDone()` 检查只依赖于实际的恢复状态，不受 `suspend()` 执行时机的影响。

关键验证点：

1. **`isUnalignedDuringRecoveryEnabled` 为 false 时不影响已有行为**：本次改动与 `useBufferFilteringFuture` 标志无关，仅改变了返回的 future 对象。无论该标志为 true 还是 false，`recoveredFutures` 中使用 `getStateConsumedFuture()` 或 `getBufferFilteringCompleteFuture()` 的逻辑不受影响。`suspend()` 仍然会在所有 recovery future 完成后被调用，mailbox 循环仍然会被正确终止。
2. **线程安全**：`suspend()` 内部通过 `mailbox.runExclusively()` 保证了线程安全，本次改动不改变任何并发语义。
3. **Mailbox 中断处理的正确性**：`suspend()` 仍然通过 `thenRun` 被触发，poison mail 仍然会被投递到 mailbox 中。唯一的区别是返回给调用方的 future 不再等待 `suspend()` 完成，这正是修复的关键。
